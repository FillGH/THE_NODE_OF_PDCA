# ข้อเสนอ DESIGN · แก้ Node ด้วยปุ่มเดียว

สถานะ: อนุมัติให้นำแบบไปพัฒนาบนสาขาแยก · ฐาน BUILD 2 `760ca9a` · ต้นแบบใช้ข้อมูลสมมติ

จากการตรวจรับ BUILD 2 หลังเปิด Node ผู้ใช้ต้องกด **แก้ในแท็บนี้** ที่หัวผัง แล้วกด **แก้ Node นี้** ใน Inspector ปุ่มใน Inspector ถูกปิดไว้จนกว่าจะกดที่หัวผัง จึงต้องค้นหาคำสั่งอีกตำแหน่งทั้งที่รู้แล้วว่าต้องการแก้ Node ใด ข้อเสนอคือให้กด **แก้ Node นี้** ครั้งเดียว แล้วระบบจัดการสิทธิ์ของแท็บและ Node พร้อมกัน สถานะผู้แก้และสถานะ Auto-save ที่ BUILD 2 มีอยู่แล้วเป็นข้อมูลที่ควรแสดงต่อ [การแสดงสิทธิ์ในหัวผัง](../web/workspaces.js#L41) · [การเปิดปุ่มใน Inspector](../web/canvas.js#L670)

## พฤติกรรมที่เสนอ

1. **เปิดอ่าน** · คลิก Card หรือเข้าจากผลค้นหาเพื่อเปิด Inspector อ่านได้โดยไม่ขอสิทธิ์ ปุ่ม **แก้ Node นี้** อยู่เหนือช่องข้อมูล ข้อความเมื่อถูกล็อกระบุชื่อผู้แก้และรหัสย่อสำหรับแยกชื่อซ้ำ
2. **เริ่มแก้** · กด **แก้ Node นี้** ระบบแสดง **กำลังขอสิทธิ์…** และเปิดช่องเมื่อ Host ยืนยันทั้งสองสิทธิ์ คงตำแหน่ง Inspector และย้ายโฟกัสไป Title สำหรับการเริ่มแก้ครั้งแรก ผู้ใช้ Tab ไป Content ได้ทันที การอัปเดตจากผู้อื่นและ Auto-save ไม่ดึงโฟกัสระหว่างพิมพ์
3. **จบหรือย้าย Node** · กด **จบการแก้** เพื่อรอ Auto-save และงานแนบที่ค้างก่อนปล่อยล็อก Node หากแท็บได้รับสิทธิ์จากการแก้ Node ครั้งนี้ ให้คืนสิทธิ์แท็บด้วย หากเปิด **แก้ผัง** ไว้อย่างชัดเจน ให้คงสิทธิ์แท็บจนกด **จบการแก้ผัง** การปิด Inspector หรือเลือก Node อื่นใช้การจบแบบเดียวกัน ถ้าบันทึกล้มเหลวหรือผลยังไม่ชัด ให้คงหน้าปัจจุบันและแสดง **ตรวจฉบับร่าง** หรือสถานะรอผลตามจริง
4. **แก้ผัง** · คงทางเข้าที่หัวผังสำหรับงานระดับผัง เช่น เพิ่ม Node เปลี่ยนชื่อ ลากตำแหน่ง และแก้เส้น ปุ่มชื่อ **แก้ผัง** และ **จบการแก้ผัง** งานแก้ Node เริ่มได้จาก Inspector โดยไม่ต้องผ่านทางเข้านี้ ใช้สิทธิ์แท็บเดียวกันในการตรวจคำขอเขียนระดับผัง

| กรณีขัดจังหวะ | สิ่งที่ผู้ใช้เห็นและทำได้ |
| --- | --- |
| Node มีผู้แก้จากอีก Session | ยังเห็นฉบับล่าสุดที่บันทึกแล้ว ปุ่มแก้ใช้ไม่ได้พร้อมคำอธิบาย **กำลังแก้โดย …** ไม่มีคิวขอสิทธิ์อัตโนมัติ สามารถเลือก Node อื่นได้ |
| อีกแท็บใน Session เดียวกันถือสิทธิ์ | แสดง **ย้ายมาแก้ Node นี้** ที่ Inspector ส่งคำขอไปยังแท็บเดิม เมื่อแท็บเดิมยืนยันว่าจัดการงานค้างและคืนสิทธิ์แล้ว ให้ขอสิทธิ์ของ Node ที่ผู้ใช้เลือกต่อจากคำสั่งเดิม ถ้าเปลี่ยน Node ออกจากผัง หรือจบ Session ระหว่างรอ ให้ยกเลิกเจตนาเดิม |
| แท็บเดิมยังบันทึกหรือมีร่างค้าง | ถ้ากำลังบันทึก ให้รอผลตาม flow เดิม ถ้าบันทึกล้มเหลวหรือยังมีร่าง ให้แจ้ง **มีฉบับร่างในแท็บเดิม** และคงแท็บใหม่เป็นหน้าอ่าน เมื่อแท็บเดิมปิด ให้รอสิทธิ์หมดอายุ และให้ผู้ใช้กด **ตรวจฉบับร่าง** ก่อนส่งข้อมูล |
| หลุดการเชื่อมต่อหรือสิทธิ์เปลี่ยน | หยุดแก้ เก็บร่างตามขอบเขต Session เดิม กลับมาให้เทียบฉบับล่าสุดกับร่างและยืนยันก่อนส่ง ถ้าฉบับหรือสิทธิ์เปลี่ยนระหว่างตรวจให้เปิดเทียบใหม่ |

## ผลต่อการพัฒนาและเกณฑ์ตรวจรับ

ข้อกำหนด D-026–D-031 ให้ Host คุมหนึ่งแท็บแก้ไขต่อ Session ต่อ PDCA และหนึ่งผู้แก้ต่อ Node พร้อมป้ายผู้แก้ Auto-save และการกู้ร่าง ไม่พบข้อกำหนดว่าผู้ใช้ต้องกดปุ่มแยกสองครั้ง การเปลี่ยนนี้จึงเป็นข้อเสนอปรับขั้นตอน UI ที่ใช้กติกาเดิม [PROJECT.md](../PROJECT.md#L126) · [เกณฑ์ C-01–C-11](qa/COLLABORATION_ACCEPTANCE.md)

- ใช้คำขอเริ่มแก้หนึ่งครั้งที่ Host โดยตรวจว่า Session, PDCA, Node และแท็บยังมีสิทธิ์ ตรวจการชนของแท็บและ Node ก่อนสร้างสิทธิ์ทั้งสองในขั้นตอนเดียว ไม่สร้างสิทธิ์แท็บใหม่ค้างเมื่อ Node ถูกล็อก หากแท็บมีสิทธิ์เดิมอยู่แล้วให้ใช้สิทธิ์นั้น ทำคำขอซ้ำสำหรับแท็บและ Node เดิมให้ได้ผลเดิมขณะสิทธิ์ยังมีอายุ และตรวจคู่ token กับ revision ตอนบันทึกตาม BUILD 2 [Host ปัจจุบัน](../src/collaboration.js#L76) · [เส้นทางคำขอปัจจุบัน](../src/server.js#L114)
- ระหว่างรอให้ระงับการเริ่มซ้ำ ตอบกลับได้เฉพาะเจตนาล่าสุดของ Session/ผัง/แท็บ/Node ถ้าคำตอบมาช้าหลังผู้ใช้ย้ายหน้า ห้ามเปิดช่องแก้ย้อนหลังและคืนสิทธิ์ที่เพิ่งได้หากยังเป็นของคำขอเดิม ใช้การหมดอายุตาม BUILD 2 สำหรับแท็บที่หาย เมื่อผลเริ่มแก้ไม่ชัด ให้ตรวจสถานะ Host ก่อนลองใหม่
- ตรวจจากหน้าจอว่าเปิดอ่านใช้ **0 คำสั่งเริ่มแก้** และจาก Inspector ถึงพิมพ์ใช้ **1 คำสั่งเริ่มแก้** ในกรณีปกติ ทั้งเมาส์และคีย์บอร์ด ตรวจว่า Auto-save ยังแสดงกำลังบันทึก สำเร็จ หรือล้มเหลวตามจริง และข้อความสถานะอ่านได้โดยไม่อาศัยสีอย่างเดียว
- ตรวจซ้ำ C-01, C-05–C-07 กับ flow ใหม่ รวมคลิกพร้อมกัน คนละ Node ย้ายแท็บตอนมีร่าง และหลุดการเชื่อมต่อ เพิ่มกรณีคำขอถูกปฏิเสธแล้วแท็บพี่น้องยังเริ่มแก้ Node อื่นได้ และกรณีผลตอบกลับช้าหลังปิด Inspector ใช้ C-02–C-04 และ C-08–C-11 ตรวจถดถอยตามเส้นทางที่กระทบ เก็บผลเดิมของ `760ca9a` เป็นหลักฐานของ baseline เดิม
