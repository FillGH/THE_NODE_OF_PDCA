เริ่มใช้งาน — ไม่ต้อง Copy คำสั่ง

ครั้งแรก: แตก ZIP ชั้นนอกทั้งหมดลง Folder ใหม่ เปิด SETUP.cmd กรอก IP และ Port ที่ IT อนุมัติ (Enter ใช้ 4175 เมื่อ IT อนุมัติ) ตรวจ ACL และพิมพ์ GO เพียงครั้งเดียว ระบบจะเตรียมข้อมูลสมมติ ตรวจฐานข้อมูล และเปิด Browser ให้เอง

ครั้งต่อไป: เปิด START.cmd เท่านั้น ไม่ต้อง Seed หรือ ADOPT ซ้ำ ปิด Host ด้วย Ctrl+C หลังจัดการ Draft และปิดการเข้าถึงตาม IT policy

เก็บ _support ไว้ด้วย หากมีข้อมูลเดิม ห้าม Setup ใหม่ใน Folder เดิมหรือย้ายฐานข้อมูลเอง ให้ใช้คู่มือเดิม/IT migration หากมี STOP ให้เก็บข้อมูลทั้งหมดไว้ ไม่แก้ Firewall หรือ Execution Policy เอง

ขั้นตอนเดิมแบบ Manual (สำหรับ IT Troubleshooting เท่านั้น)

1. ระบุตำแหน่งไฟล์

สำหรับ Manual fallback เท่านั้น: ใช้ ZIP โปรแกรมและ HTML จากชุดที่ได้รับอนุมัติใน Folder เดียวกัน

ชื่อ ZIP ถูกเติมให้อัตโนมัติ หากเปลี่ยนชื่อไฟล์ให้เลือก ZIP ใหม่
ใช้ ZIP จากชุดที่ได้รับอนุมัติเท่านั้น ไม่ต้องกรอกหรือตรวจ checksum เอง
ดูด้วย ipconfig แต่ให้ IT เลือก NIC ที่ถูกต้อง
ตัวอย่างเท่านั้น ไม่ใช่การอนุมัติ

เมื่อกรอกชื่อ ZIP จะเห็น Folder ที่โปรแกรมใช้

ช่องยืนยันนี้เป็นเพียงตัวช่วย ไม่ใช่หลักฐาน IT Approval และไม่แทนการตรวจจริง

2. ติดตั้งครั้งแรก

เปิด Windows PowerShell ปกติ (ไม่ต้อง Run as Administrator เว้นแต่ IT กำหนด) แล้วคัดลอกคำสั่งทีละขั้น กด Enter และตรวจผลก่อนขั้นถัดไป

1ตรวจ ZIP และแตกไฟล์

ใช้ Node.js 24.x ตั้งแต่ 24.11.0 (Windows x64 รุ่นที่ IT อนุมัติ) ไม่ต้อง Downgrade คำสั่งตรวจ Node, แตก ZIP และตรวจ Manifest อัตโนมัติ ไม่เขียนทับ Folder เดิม

รอข้อความ PACKAGE READY
ดูคำสั่ง

2เตรียม Config และข้อมูลสมมติ

คำสั่งสร้าง Folder แยก ตรวจว่า IP/Port bind ได้ และหยุดถาม 2 ครั้ง ให้พิมพ์ GO เมื่อ IT ยืนยัน Endpoint/ข้อมูลสมมติ และตรวจสิทธิ์ NTFS จริงแล้ว จากนั้นใช้ Setup และ Seed เดิม ไม่เขียนทับข้อมูล

รอข้อความ SYNTHETIC SEED READY
ดูคำสั่ง

หากหยุดก่อนสร้าง host.env และทั้ง Folder Config/Data ยังว่างจริง สามารถกดคำสั่ง 2 ซ้ำได้หลัง IT ตรวจสิทธิ์ หากมีไฟล์ใดแล้วให้ STOP ห้ามลบ Folder / Seed ซ้ำ / แก้ Pointer เอง หากเห็น SYNTHETIC SEED READY แล้ว ให้ไปขั้น 3 เท่านั้น

3ยืนยันฐานข้อมูลครั้งแรก (ADOPT)

ให้ผู้ดูแล IT เปิด config\host.env ด้วย Notepad เฉพาะในเครื่องนี้ เพื่ออ่านค่า PDCA_IT_KEY (ไม่รวมเครื่องหมายคำพูด) ปิดไฟล์โดยไม่บันทึก ห้ามส่ง Key หรือภาพหน้าจอที่มี Key

ดูคำสั่ง
  1. กรอก IT Key ในช่องที่ไม่แสดงตัวอักษร
  2. เลือก 3 แล้วพิมพ์ ADOPT
  3. เลือก 1 ตรวจ Status ต้องสำเร็จ ไม่มี Warning/Blocked/Busy และคู่ฐานถูกต้อง
  4. เลือก 0 ออกจากเมนู แล้วไปเปิดโปรแกรมด้านล่าง

3. เปิดโปรแกรม

ติดตั้งและ ADOPT สำเร็จแล้วเท่านั้น ครั้งต่อไปเปิด HTML ใน Folder app เดิม เลือก “เปิดโปรแกรมครั้งต่อไป” และใช้คำสั่งนี้ ไม่ต้อง Setup/Seed/ADOPT ใหม่

Diagnose ต้องผ่านก่อน Start
ดูคำสั่ง

เปิด URL ที่หน้าต่าง Host แสดง ใน Edge และเปิด URL เดียวกันจากเครื่องลูกข่ายที่ IT อนุญาต ห้ามใช้ข้อมูลจริง ให้หน้าต่าง PowerShell ทำงานอยู่ตลอด เมื่อหยุดงานให้บันทึกและจัดการ Draft ก่อนปิด access, กด Ctrl+C แล้วตรวจว่า process จบ

ถ้าเปิดไม่ได้

Node ไม่พบ / Version ไม่ตรง

ให้ IT จัด Node.js 24.x ตั้งแต่ 24.11.0 ขึ้นไปที่อนุญาตและมี Security Patch เหมาะสม หากอัปเดต Runtime ให้ทดสอบเปิด/บันทึก/Backup/Recovery ก่อนใช้จริง ไม่ติดตั้ง npm package หรือดาวน์โหลด Registry บน Target

แตก ZIP ไม่สำเร็จ / Manifest ไม่ตรง หรือมี Folder เดิม

STOP ใช้ ZIP จากชุดที่ได้รับอนุมัติ ห้ามแก้ไฟล์ใน app หรือแตกทับเดิม หากมี Config/Data เดิมใช้ Daily Start หรือ Migration ที่ได้รับการตรวจ

IP/Port ไม่ผ่าน / เครื่องอื่นเข้าไม่ได้

ให้ IT ตรวจ assigned private IP, port bind, Firewall/ACL/NAC, guest/VPN/Internet และ access revocation ห้ามเปลี่ยนเป็น 0.0.0.0, ปิด Firewall หรือข้าม IT policy

หยุดกลางทาง ต้องเริ่มตรงไหน?

หาก Windows แจ้ง Path ยาวเกินไป ให้ย้ายชุดไฟล์ไป Folder สั้นลงก่อนติดตั้งใหม่ ถ้า PACKAGE READY แล้ว ไม่ต้องแตก ZIP ซ้ำ ไปขั้น 2 ได้เลย ถ้าหยุดก่อนสร้าง Config/DB และ Folder ยังว่างจริง ให้รันขั้น 2 ซ้ำได้ หาก Seed สำเร็จแล้วและยังไม่ ADOPT ให้ทำขั้น 3 หลัง IT ยืนยันข้อมูลสมมติเดิม ถ้าไม่ทราบสถานะหรือมีไฟล์บางส่วน ให้ IT ตรวจ ห้ามลบหรือ Seed ทับ

ADOPT / Status / Recovery ไม่ผ่าน

หยุด Host ทั้งหมด เก็บข้อมูลและหลักฐานเดิม ให้ IT ตรวจคู่ Workspace/Audit และ Active Pointer ห้าม Seed ซ้ำ แก้ DB/Pointer หรือลบ Host Exclusion Lock

สำหรับ IT — การดูแลและตรวจรับ

Backup บน Host เมื่อ Start และทุก 2 ชั่วโมง, retention 30 วัน; ทั้ง Host เสียหายอาจกู้ไม่ได้ Off-host ขึ้นกับ IT policy และต้องรักษาคู่ Workspace/Audit ที่ถูกต้อง RPO ≤4 ชั่วโมง / RTO ≤1 วันทำการ เมื่อมี Backup และ Infrastructure ที่ยังใช้ได้ ต้องซ้อมจริง

Restore/Migration/ACTIVATE/ROLLBACK ทำตามคู่มือเดิมโดยผู้มีสิทธิ์และหยุดทุก Writer ก่อน; ห้ามคัดลอก Live SQLite Pair หรือแก้ Pointer เอง สำหรับ Task Scheduler หลัง IT GO ใช้ Start CMD และ absolute external host.env; ตรวจ reboot/backup และหยุด auto-restart ระหว่าง maintenance
