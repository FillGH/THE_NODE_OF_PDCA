ก่อนเปิด LAN ให้ IT ยืนยันเครื่อง, IP/Port, สิทธิ์เข้าถึงและ ACL รวมถึงความเสี่ยง HTTP (ไม่เข้ารหัส; Display Name ไม่ใช่การยืนยันตัวตน) ห้ามเปิดให้ Guest/VPN/Internet หรือเครื่องที่ไม่ได้รับอนุญาต หาก IT กำหนด TLS ให้หยุด ไม่เปลี่ยน Firewall หรือ Policy เอง

1. ระบุตำแหน่งไฟล์

วาง HTML, Inner ZIP และไฟล์ .sha256 ไว้ใน Folder เดียวกัน (ถ้าดาวน์โหลด Actions Artifact ให้แตก ZIP ชั้นนอกก่อน) เปิด HTML ด้วย Edge โดยไม่ต้องเปิด Server

เลือกไฟล์ด้านล่างเพื่อเติมชื่ออัตโนมัติ หรือกรอกชื่อเดิมสำหรับ Daily Start
ใช้ Hash ของ Inner ZIP ใน Approval Record ไม่ใช่ Hash ของ ZIP ชั้นนอก
ดูด้วย ipconfig แต่ให้ IT เลือก NIC ที่ถูกต้อง
ตัวอย่างเท่านั้น ไม่ใช่การอนุมัติ

เมื่อกรอกชื่อ ZIP จะเห็น Folder ที่โปรแกรมใช้

ช่องยืนยันนี้เป็นเพียงตัวช่วย ไม่ใช่หลักฐาน IT Approval และไม่แทนการตรวจจริง

2. ติดตั้งครั้งแรก

เปิด Windows PowerShell ปกติ (ไม่ต้อง Run as Administrator เว้นแต่ IT กำหนด) แล้วคัดลอกคำสั่งทีละขั้น กด Enter และตรวจผลก่อนขั้นถัดไป

1ตรวจ ZIP และแตกไฟล์

ต้องมี Node.js 24.11.0 ที่ IT อนุมัติแล้ว คำสั่งตรวจ Node, SHA-256, sidecar, Manifest และไม่เขียนทับ Folder เดิม

รอข้อความ PACKAGE READY
ดูคำสั่ง

2เตรียม Config และข้อมูลสมมติ

คำสั่งสร้าง Folder แยก ตรวจว่า IP/Port bind ได้ และหยุดให้ IT ตรวจสิทธิ์ NTFS ก่อนสร้าง Key/DB จากนั้นใช้ Setup และ Seed เดิม ไม่เขียนทับข้อมูล

รอข้อความ SYNTHETIC SEED READY
ดูคำสั่ง

ถ้ามี Config หรือ Data เดิม หรือขั้นตอนล้มเหลว ให้หยุด ห้ามลบ Folder / Seed ซ้ำ / แก้ Pointer เอง ใช้คู่มือ Migration หรือให้ IT ตรวจ

3ยืนยันฐานข้อมูลครั้งแรก (ADOPT)

ให้ผู้ดูแล IT เปิด config\host.env ด้วย Notepad เฉพาะในเครื่องนี้ เพื่ออ่านค่า PDCA_IT_KEY (ไม่รวมเครื่องหมายคำพูด) ปิดไฟล์โดยไม่บันทึก ห้ามส่ง Key หรือภาพหน้าจอที่มี Key

ดูคำสั่ง
  1. กรอก IT Key ในช่องที่ไม่แสดงตัวอักษร
  2. เลือก 3 แล้วพิมพ์ ADOPT
  3. เลือก 1 ตรวจ Status ต้องสำเร็จ ไม่มี Warning/Blocked/Busy และคู่ฐานถูกต้อง
  4. เลือก 0 ออกจากเมนู แล้วไปเปิดโปรแกรมด้านล่าง

3. เปิดโปรแกรม

ติดตั้งและ ADOPT สำเร็จแล้วเท่านั้น ครั้งต่อไปเปิด HTML ใน Folder app เดิม เลือก “เปิดโปรแกรมครั้งต่อไป” และใช้คำสั่งนี้ ไม่ต้อง Setup/Seed/ADOPT ใหม่

Diagnose ต้องผ่านก่อน Start
ดูคำสั่ง

เปิด URL ที่หน้าต่าง Host แสดง ใน Edge และเปิด URL เดียวกันจากเครื่องลูกข่ายที่ IT อนุญาต ห้ามใช้ข้อมูลจริง ให้หน้าต่าง PowerShell ทำงานอยู่ตลอด เมื่อหยุดงานให้บันทึกและจัดการ Draft ก่อนปิด access, กด Ctrl+C แล้วตรวจว่า process จบ

ถ้าเปิดไม่ได้

Node ไม่พบ / Version ไม่ตรง

ให้ IT จัด Node.js 24.11.0 ที่อนุญาต ไม่ติดตั้ง npm package หรือดาวน์โหลด Registry บน Target

Hash / Manifest ไม่ตรง หรือมี Folder เดิม

STOP ใช้ Inner ZIP และ Hash ที่อนุมัติ ห้ามแก้ไฟล์ใน app หรือแตกทับเดิม หากมี Config/Data เดิมใช้ Daily Start หรือ Migration ที่ได้รับการตรวจ

IP/Port ไม่ผ่าน / เครื่องอื่นเข้าไม่ได้

ให้ IT ตรวจ assigned private IP, port bind, Firewall/ACL/NAC, guest/VPN/Internet และ access revocation ห้ามเปลี่ยนเป็น 0.0.0.0, ปิด Firewall หรือข้าม IT policy

ADOPT / Status / Recovery ไม่ผ่าน

หยุด Host ทั้งหมด เก็บข้อมูลและหลักฐานเดิม ให้ IT ตรวจคู่ Workspace/Audit และ Active Pointer ห้าม Seed ซ้ำ แก้ DB/Pointer หรือลบ Host Exclusion Lock

สำหรับ IT — การดูแลและตรวจรับ

Backup บน Host เมื่อ Start และทุก 2 ชั่วโมง, retention 30 วัน; ทั้ง Host เสียหายอาจกู้ไม่ได้ Off-host ขึ้นกับ IT policy และต้องรักษาคู่ Workspace/Audit ที่ถูกต้อง RPO ≤4 ชั่วโมง / RTO ≤1 วันทำการ เมื่อมี Backup และ Infrastructure ที่ยังใช้ได้ ต้องซ้อมจริง

Restore/Migration/ACTIVATE/ROLLBACK ทำตามคู่มือเดิมโดยผู้มีสิทธิ์และหยุดทุก Writer ก่อน; ห้ามคัดลอก Live SQLite Pair หรือแก้ Pointer เอง สำหรับ Task Scheduler หลัง IT GO ใช้ Start CMD และ absolute external host.env; ตรวจ reboot/backup และหยุด auto-restart ระหว่าง maintenance
